2. Hubungkan Clerk ke aplikasi tanpa menyimpan credential di source atau

3. Implementasikan/verifikasi lifecycle actor berikut dan UJI SATU PER SATU
   dengan Clerk sungguhan (bukan mock), rekam hasilnya:
   a. Sign-in sukses → session dibuat, tercatat di audit log dengan actor,
      tenant, timestamp.
   b. Callback OAuth/email identity dari Clerk → user internal dipetakan
      HANYA melalui aturan immutable yang diaudit (external ID → internal
      user ID tidak boleh berubah diam-diam).
   c. Logout → session di-revoke, cookie dihapus, request selanjutnya dengan
      cookie lama ditolak.
   d. Expired session → request ditolak dengan kode error yang jelas.
   e. Revoked session (revoke manual dari admin) → request berikutnya ditolak
      SEBELUM expiry alami.
   f. Disabled/removed membership → user tidak bisa lagi mengakses tenant
      tersebut meski session masih valid.
   g. Account recovery flow Clerk (reset password/email) diuji end-to-end.
4. Uji invitation lifecycle pada database PostgreSQL nyata (bukan in-memory):
   invitation accept, duplicate invitation attempt (harus ditolak), invitation
   expiry, invitation revoke, replay attack pada invitation token yang sama
   (harus ditolak), dan ownership transfer antar admin.
5. Uji cross-tenant access denial di DUA layer: HTTP boundary (request dengan
   token tenant A mencoba akses resource tenant B → harus 403/404, bukan
   bocor data) DAN service/repository boundary (query di level kode juga
   harus tenant-scoped, bukan hanya disaring di controller).
6. Uji CSRF protection, cookie flags (httpOnly, secure, sameSite), session
   rotation setelah privilege change, dan pastikan dev auth benar-benar
   tidak bisa diaktifkan di production (ulangi test poin 2 sebagai regression).
